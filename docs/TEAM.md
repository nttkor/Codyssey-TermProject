## 커밋 수 산정

`git log 9d09c28 --no-merges`를 기준으로 author 이름과 이메일을 구분하고,
부모 대비 변경이 없는 빈 커밋을 제외한다. 기능·테스트·문서·수정 모두 실제 변경이 있으면 집계 대상이다.

| 팀원 | 병합 제외 | 빈 커밋 제외 |
| --- | ---: | ---: |
| 김창환 | 31 | 31 |
| 이현민 — AI·배포 | 32 | 32 |
| 김동조 | 18 (nttkor 16 + 실명 2) | 18 |
| 이현민 — leehnmn | 13 | 12 |

`06c8b73`은 변경 없는 커밋이라 제외했다. leehnmn의 `c971737`은 로그인 화면을 잘못 바꾼 변경이며
`edf4e06`은 이를 복구한다. 이 쌍까지 보수적으로 제외하면 10개이다.
`3c3a6a8`은 제목이 “Add files via upload”이지만 history.js 122줄을 추가한 실제 구현이다.
이 수량은 평가 근거이며, 모든 커밋의 유의미성을 자동으로 보장하는 점수는 아니다.

검토 명령:

```bash
git log 9d09c28 --no-merges --format='%h %an <%ae> %s' --numstat
git show 06c8b73
git diff c971737^ edf4e06 -- backend/app/templates/login.html
```

첫 명령은 개인별 실제 변경을 보여준다. 마지막 명령의 출력이 없으면 해당 변경·복구 쌍의
로그인 화면에 대한 최종 차이가 없다는 뜻이다. 이후 작업을 추가할 때는 집계 기준 SHA도 함께 갱신한다.
