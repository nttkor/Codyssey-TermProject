## 4. 개선이 필요한 사항

### 4-1. `main` 브랜치에 애플리케이션 미통합 (중요)

- `main`은 4커밋(README, CONVENTIONS, .github 템플릿)만 존재하고 백엔드/프론트/배포/나머지 문서가 전혀 없습니다. 전체 구현은 `develop`(115커밋)에만 있습니다.
- 저장소 기본 브랜치는 `main`(`origin/HEAD → origin/main`)이므로, 평가자가 기본 브랜치를 열면 사실상 빈 프로젝트를 보게 됩니다.
- `CONVENTIONS.md`가 스스로 정의한 "`develop → main` 병합으로 배포 기준 갱신" 흐름이 아직 완료되지 않았습니다.
- **권장 조치**: 평가/시연 전에 `develop → main` PR을 병합해 기본 브랜치에서도 전체 코드·문서가 보이도록 정리.

### 4-2. 문서와 구현 불일치 (문서 최신화)

  - `README.md`: "로그인 폼과 기록 목록 등 화면 연동은 아직 구현되지 않았습니다" → 실제로는 로그인/회원가입/채팅/기록 화면 모두 구현됨.

모든 요청/응답 스키마는 Pydantic `BaseModel`로 정의됩니다.

```python
# backend/app/account.py
class SignUpPayload(BaseModel):
    username: Username          # 3~30자, 영숫자·밑줄, 소문자 변환
    password: Annotated[SecretStr, Field(min_length=8, max_length=128)]

class UserResponse(BaseModel):
    id: int
    username: str

# backend/app/llm.py
class ChatRequest(BaseModel):
    question: Annotated[
        str, StringConstraints(strip_whitespace=True, min_length=1, max_length=1000)
    ]
```

> **⚠️ 불일치 수정 필요**: `docs/API.md`의 비밀번호 "15~128자" → **"8~128자"** 로 수정 필요.  
> 실제 구현은 `account.py` `min_length=8`, `signup.js` 56행 `password.length < 8` 이 기준.

**기술 설명**

SQLAlchemy ORM의 `DeclarativeBase`를 상속한 두 테이블이 존재합니다.

```python
# backend/app/models/user.py
class User(Base):
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(primary_key=True)
    username: Mapped[str] = mapped_column(String(30), unique=True)
    password_hash: Mapped[str] = mapped_column(Text)
    created_at: Mapped[datetime] = mapped_column(
        DateTime, default=lambda: datetime.now(UTC).replace(tzinfo=None)
    )

# backend/app/models/chat.py
class Chat(Base):
    __tablename__ = "chats"
    id: Mapped[int] = mapped_column(primary_key=True)
    user_id: Mapped[int] = mapped_column(ForeignKey("users.id"), index=True)
    question: Mapped[str] = mapped_column(Text)
    answer: Mapped[str] = mapped_column(Text)
    created_at: Mapped[datetime] = mapped_column(
        DateTime, default=lambda: datetime.now(UTC).replace(tzinfo=None)
    )
```

회원가입 전체 흐름:

```
[signup.js] 클라이언트 검증
  → username 패턴 /^[a-zA-Z0-9_]{3,30}$/ 검사
  → password 8~128자 검사
  → password 일치 검사
  → POST /api/signup (X-Requested-With: XMLHttpRequest 헤더 포함)

  → 201 Created + {id, username} 반환

[signup.js] 성공 시 /login?registered=1 로 이동
```

```python
# backend/app/account.py
@router.post("/signup", status_code=201, response_model=UserResponse,
    dependencies=[Depends(require_csrf_header)])
def signup(payload: SignUpPayload, db: Annotated[Session, Depends(get_db)]) -> UserResponse:
    password_hash = hash_password(payload.password.get_secret_value())
    try:
        user_id = create_user(db, payload.username, password_hash)
    except SQLAlchemyError as exc:
        if isinstance(exc, IntegrityError) and exc.orig.sqlite_errorcode == SQLITE_CONSTRAINT_UNIQUE:
            raise HTTPException(status_code=409, detail="이미 사용 중인 사용자명입니다.")
        raise HTTPException(status_code=500, detail="회원가입 정보를 저장하지 못했습니다.")
    return UserResponse(id=user_id, username=payload.username)
```

```python
# backend/app/chat_db.py
def create_chat(db: Session, user_id: int, question: str, answer: str) -> int:
    chat = Chat(user_id=user_id, question=question, answer=answer)
    db.add(chat)
    try:
        db.flush()
        chat_id = chat.id
        db.commit()
    except SQLAlchemyError:
        db.rollback()
        raise
    return chat_id
```

### 11-1. 주요 코드 결함 수정 사항

1. **비정상 AI 응답 검증 및 안전한 502 변환 (`c0d0fe3`)**
   - **문제**: 외부 AI 게이트웨이가 HTTP 200을 반환하더라도 `choices`가 누락/빈배열이거나, `content`가 문자열이 아니거나 빈 공백일 경우, 또는 비정상 JSON 응답일 때 애플리케이션 예외가 발생하거나 비정상 데이터가 DB에 저장될 위험 존재.
   - **수정**: `backend/app/llm_connect.py`에서 `(OpenAIError, JSONDecodeError)`를 포착하고, `content`의 문자열 여부 및 `strip()` 검사를 거쳐 `InvalidAnswer`/`EmptyAnswer` 에러 로깅 후 `AIServiceError(502)`로 일관되게 변환. 비정상 응답 시 질문·답변은 DB에 저장되지 않으며, 사용자에게는 내부 에러 원문이나 API 키를 노출하지 않고 안전한 안내 메시지만 반환.

2. **`AI_TIMEOUT` 유한한 양수 엄격 검증 (`4f0a906`)**
   - **문제**: `AI_TIMEOUT`에 `nan`, `inf`, `-inf`, `1e999`, `0.0`, 음수 등이 입력될 경우 무한 대기 또는 의도치 않은 예외 발생 위험.
   - **수정**: `backend/app/config_validation.py`를 신설하여 `math.isfinite(timeout) and timeout > 0` 검증 구현. 앱 기동(`config.py`)과 GitHub Actions OCI 배포 워크플로(`.github/workflows/deploy-oci.yml`) 사전 검사에서 동일한 로직을 공유하여 배포와 런타임 간 환경 변수 불일치 방지.

3. **로그아웃 실패 처리 및 재시도 지원 (`90ac4ad`)**
   - **문제**: 로그아웃 API 요청이 500 오류나 네트워크 장애로 실패해도 무조건 로그인 페이지(`/login`)로 이동하여 사용자가 정상 로그아웃된 것으로 착각할 수 있는 결함.
   - **수정**: `backend/app/static/js/common.js`에서 오직 HTTP 204 No Content일 때만 `/login`으로 이동하도록 변경. 실패(200, 401, 403, 500, 네트워크 실패) 시 이동 없이 화면에 머물며 상단 `#logoutError` 배너를 통해 오류 안내를 표시하고, 버튼을 즉시 다시 활성화하여 재시도 허용. 대기 중 중복 클릭 방지 처리.

4. **한글 IME 조합 중 Enter 전송 방지 (`6dd87f9`)**
   - **문제**: macOS/Windows 등에서 한글 입력 시 마지막 자모 조합을 확정하기 위해 누른 Enter 키로 인해 질문이 미완성 상태에서 즉시 전송되는 버그.
   - **수정**: `backend/app/static/js/chat.js`에 `compositionstart`, `compositionend` 이벤트 리스너를 추가하여 조합 상태(`isComposing`)를 추적하고, `keydown` 핸들러에서 `isComposing || e.isComposing || e.keyCode === 229`일 경우 제출을 차단. 일반 Enter는 1회 전송, `Shift + Enter`는 줄바꿈 유지.
